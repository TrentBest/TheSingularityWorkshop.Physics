# Terrain height-field experience

## Question

How does a bounded surface encode elevation, and how can a local authoring operation change that surface without mutating the original snapshot?

## Model

The experience uses `TheSingularityWorkshop.Physics.Geology.TerrainHeightField2D`, a cell-centred, immutable 2D elevation field. The checked-in run record is generated by `tools/TerrainHeightFieldRunRecordGenerator` from the Physics API.

- Grid: 17 × 17 samples, row-major with X varying fastest.
- Horizontal spacing: 1 m × 1 m.
- Origin: (-8 m, -8 m).
- Coordinate frame: `local-east-north`.
- Vertical datum: `local-zero`; positive vertical direction: `up`.
- Base shape: parabolic bowl with 20 m rim elevation, 8 m depth, centre (0 m, 0 m), and 8 m radius.
- Edit: a smooth radial brush centred at (-2 m, 2 m), radius 3 m, with +2 m elevation delta.

The run record preserves both the original and edited elevation arrays, the stable brush operation ID, algorithm version, authoring-source identity, changed-sample count, and sample-aligned dirty region. The Pages view only projects those recorded values into an isometric SVG and a centre-row profile.

## What to inspect

1. Switch between **Original bowl** and **Brush-edited surface**.
2. Select a diamond to inspect its grid index, world coordinates, elevation, and edit delta.
3. Compare the centre-row profile.
4. Download the JSON record and inspect the full row-major arrays.

## Interpretation boundary

The bowl and brush are geometric authoring operations. They do not model volcanic formation, erosion, tectonic uplift, sediment transport, or water flow. The height field is 2.5D and cannot represent caves, overhangs, vertical faces, or multiple surface layers.
