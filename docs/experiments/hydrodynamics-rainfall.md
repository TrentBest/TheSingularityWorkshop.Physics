# Hydrodynamics: rainfall accumulation run

This reproducible experiment generates recorded states from the actual `BathymetricShallowWaterBasin2D` implementation. It is a consumer handoff artifact for downstream demonstrations; it is not a second solver or a rendered approximation.

## Scenario

- Grid: 12 × 8 row-major cells, each 1 m × 1 m.
- Initial water depth: 0 m in every cell.
- Bed: fixed and flat at 0 m.
- Rain: a localized 4 × 2 cell patch at 0.00002 m/s water-equivalent precipitation rate.
- Solver step: 0.05 s.
- Duration: 60 s (1,200 steps).
- Operation order: apply one 0.05 s rainfall increment, then advance the basin once; repeat.
- Boundaries: impermeable closed walls.

The expected rainfall input is:

\[
V_{rain}=\left(8\;cells\times 0.00002\;\frac{m}{s}\right)
\times 60\;s\times 1\;m^2
=0.0096\;m^3
\]

With no infiltration, evaporation, drainage, or open-boundary flow in this experiment, the final basin water volume should match that input within the recorded 1e-10 m³ tolerance. This is a water-accounting check, not a claim of spatial accuracy or validated runoff behavior.

## Generate the record

From the repository root:

```bash
dotnet run --project tools/HydrodynamicsRainfallRunRecordGenerator/HydrodynamicsRainfallRunRecordGenerator.csproj --configuration Release -- /tmp/hydrodynamics-rainfall.run.json
python3 tools/validate_physics_run_records.py /tmp/hydrodynamics-rainfall.run.json
```

The JSON contains:
- model identity, units, complete scenario definition, and Physics source revision;
- actual basin snapshots at 0, 15, 30, 45, and 60 seconds;
- per-cell depth arrays and basin volume at each recorded time;
- final depth field, rainfall input volume, final water volume, and balance residual;
- explicit validation flags and model limitations.

Set `PHYSICS_SOURCE_REVISION` to the exact Physics commit SHA when generating a handoff artifact. The repository CI workflow does this automatically and uploads the generated JSON as the `hydrodynamics-rainfall-run-record` artifact. The artifact is generated by the C# model on that workflow run; no hand-authored water values are used.

## Reproduce and validate

The generator accepts `--check` after the output path to compare an existing record byte-for-byte with a fresh run under the same source revision:

```bash
PHYSICS_SOURCE_REVISION=<commit-sha> dotnet run --project tools/HydrodynamicsRainfallRunRecordGenerator/HydrodynamicsRainfallRunRecordGenerator.csproj --configuration Release -- /tmp/hydrodynamics-rainfall.run.json --check
```

The CI validation additionally checks the model identity, pinned source revision, sample times, grid dimensions, finite non-negative depths, completed logical time, and the expected rainfall-to-volume balance.

## Limits

This experiment uses the existing depth-averaged 2D shallow-water model. Rainfall adds water-equivalent depth and no horizontal momentum. It does not model infiltration, evaporation, drainage, runoff routing, droplets, splashes, fountains, spray, optics, or 3D flow. The closed basin prevents external water loss; the experiment therefore does not validate an open drainage system or realistic surface runoff.

The run record is authoritative for the numerical state it contains. A consumer may derive mesh vertices and presentation normals from the captured bed and free-surface arrays, but those presentation quantities must not be presented as additional Physics outputs.
