# Contact Observation Contract

**Status:** implemented value contract; contact detection and response are not implemented by this type.

## What one record means

`ContactObservation` captures evidence supplied by a contact-producing model for two distinct bodies at one logical simulation step. It does not create that evidence: no narrowphase collision detection, friction solver, support inference, or body-state mutation is performed here.

| Field | Meaning |
|---|---|
| Contact/body IDs | Stable identities assigned by the producing model; IDs are not generated by this record |
| Point | World-frame contact point, metres |
| Normal | Unit vector from body A toward body B |
| Relative velocity | World-frame velocity of B minus A, metres/second |
| Signed separation | Metres; negative is penetration, zero is touching, positive is a gap accepted by the producing model's tolerance |
| Active | Whether the producing model considers the contact active at this step |
| Normal force | Optional non-negative magnitude in newtons |
| Normal impulse | Optional non-negative magnitude in newton-seconds |
| Step/time | Zero-based logical step and elapsed logical time in seconds |

The constructor requires a unit normal within a documented numerical tolerance and rejects invalid identities, self-contact, non-finite separation/time, negative/non-finite load values, and negative step indices. A default-initialized record is invalid. Optional load values are null when the source did not compute them; null is not zero.

## Interpretation limits

- Active contact is not proof of support. Support requires a model that accounts for load, gravity, friction, and the intended support criterion.
- Force and impulse are distinct measurements and are not substituted for one another.
- This initial contract describes body pairs, not individual collider/shape pairs. Extend identity granularity only when the owning collision model has stable shape identities.
- No collision detector, contact persistence tracker, friction model, solver, or rigid-body integrator is implied.

## Tests

The test suite checks identity and geometry preservation, signed separation, logical step/time, optional load availability, invalid defaults, non-unit normals, self-contact, and invalid optional load/time values.
