# Physics Pages client

This directory is the first static WebApp-style client for the Physics repository. It is designed for GitHub Pages hosting and does not require ServerApp.

## Run locally

Serve this directory over HTTP (for example, `python3 -m http.server 8000 --directory site`) and open `http://localhost:8000`. A local HTTP server is required because the client fetches the run-record JSON.

## First vertical slice

- **Atlas:** domain entry points with explicit implementation-status language, plus a landing-page evidence gallery that previews the actual projectile and terrain run records. Each gallery card states its proof and scientific limits.
- **Projectile experience:** a recorded 3D point-projectile trajectory from the actual Physics generator.
- **Terrain experience:** a 17 × 17 height field generated by the actual `TerrainHeightField2D` API, with base/edited comparisons, an isometric sample view, centre-row profile, and per-cell inspection.
- **Evidence inspector:** selected sample state and the complete recorded sample table.
- **Navigation FSM:** `HOME`, `PROJECTILE`, `INSPECTOR`, and `FSM`, with semantic transitions and hash-based browser navigation.
- **FSM inspector:** the System navigation entry exposes the live transition table, current route, allowed actions, and history fallback behavior. It inspects the actual presentation state machine; it is not a Physics simulation.
- **Navigation tests:** Node tests cover route parsing, deep-link mapping, valid transitions, and rejected actions; the Pages build runs them before producing the artifact.
- **No browser-side solver:** the charts, gallery previews, and inspectors read the checked-in JSON records. They do not independently calculate physical outcomes.
- **Visitor paths:** the landing page separates hands-on exploration, theory/source study, and contribution/evidence review.

## Evidence contract

The Pages copies at `data/projectile-trajectory.run.json` and `data/terrain-height-field.run.json` must remain equal to their canonical records under `../docs/experiments/` and to fresh output from their corresponding .NET generators. The Pages workflow verifies all three on every relevant push and pull request.

The current record has no unique run ID or source-revision field. The client does not fabricate these values. Add them only through a deliberate, versioned provenance contract.

## Deployment

`.github/workflows/physics-pages.yml` builds and validates the static artifact on development changes and pull requests. Deployment occurs only when the workflow is manually dispatched against `development`. No automatic deployment from `master` is configured.

The first release should wait for successful CI, browser validation, confirmation of the repository's Pages settings, and explicit deployment authorization.
